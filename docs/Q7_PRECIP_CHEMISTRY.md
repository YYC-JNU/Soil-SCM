## 1. 问题描述与具体体现

### 1.1 Q7 — 降水化学（酸雨离子）从未生效

**现象**：
- `precip_chemistry_default.json` 中的酸雨离子（SO₄²⁻/NO₃⁻/NH₄⁺ 等）与 `PrecipChemConfig` 仅被配置解析，**无任何代码加载使用**
- 降水为纯水：每月 REACTION 只加 `H2O`，无 Cl⁻ 等保守离子输入
- 后果：Cl⁻ 被排水逐年淋洗（30 年 10⁻³ → 10⁻¹⁷ mol/kgw，跌 14 个数量级）；酸雨驱动土壤酸化的核心机制缺失

### 1.2 F1 — GAS_PHASE pCO₂ 硬编码（代码审查新发现）

**现象**：
- 引擎 `_build_phreeqc_input` 与初始条件 `build_phreeqc_input` 的 GAS_PHASE `-pressure 0.015` 均为**硬编码**
- `ClimateForcing` 生成的逐月 pCO₂（0.0117~0.0235 atm，随温度变化）**从未被使用**
- 后果：`temp_increase`/`precip_increase` 情景下 CO₂ 对土壤化学无反馈，"气候强迫"名存实亡

### 1.3 F2 — mineral_scale 双路径不一致（代码审查新发现）

**现象**：
- `phreeqc_engine.mineral_scale = 0.001`（实际模拟路径）
- `initial_condition.build_phreeqc_input` 硬编码 `moles * 0.1`（仅打印路径）
- 后果：同一矿物两条输入路径摩尔量差 100 倍，阶段 4 打印输入与阶段 7 引擎输入**不可比**（Q8 割裂的又一表现）

## 3. 解决方案设计

### 方案 A（Q7）：新增 `PrecipChemistry` 模块 + REACTION 集成

| 要点 | 设计 |
|------|------|
| 数据格式 | 离子以**当量浓度占比（percent）**存储（忠实于公报数据） |
| 浓度换算 | 总当量浓度 = 10^(−pH) / (H⁺占比)；某离子 mol/L = 总当量 × 占比 / 电荷数 |
| 自洽验证 | pH 5.75 + H⁺占 1.0% → 总当量 1.7783×10⁻⁴ eq/L，H⁺ = 1.7783×10⁻⁶ mol/L ✓ |
| 引擎接入 | 每月 REACTION 中 `H2O 入渗` 后追加降水离子摩尔量（× 入渗系数 0.05） |
| 查询扩展 | SELECTED_OUTPUT 增加 `F` 元素；`_parse_official_output` 同步解析 |
| 数据源 | 默认华南（广东 2025 公报），支持用户自定义 JSON（`use_custom` + `input_file`） |

### 方案 B（F1）：pCO₂ 真实传递

- 引擎 `_build_phreeqc_input`：`-pressure {forcing['pCO2']}`（逐月值）
- 初始条件 `build_phreeqc_input`：`-pressure {self.pCO2}`（初始值）

### 方案 C（F2）：MINERAL_SCALE 常量统一

- `initial_condition.py` 定义 `MINERAL_SCALE = 0.001`，`build_phreeqc_input` 引用
- `phreeqc_engine.mineral_scale` 默认值引用同一常量，双路径一致且保留可配置性

## 7. 边界说明

1. **natural 情景 pH 突升（第 8 年 ~10.3）**：仍为单层模型 + 完全混合 + 排水导致交换性 Al 耗尽，**非 Q7 引入**，需 Phase 3 多分层模型解决（已列入 ROADMAP）。
2. **离子当量平衡**：公报占比阴/阳当量约 43.8% : 56.2% 不平衡，由 PHREEQC 电荷平衡（Cl⁻ 补足）在计算内部处理。
3. **降水离子浓度量级**：总当量 1.78×10⁻⁴ eq/L 属华南酸雨典型量级，与公报数据自洽。
4. **F1 对既有结果的影响**：pCO₂ 从恒 0.015 变为随季节波动（冬季低、夏季高），模拟结果已反映该变化。
