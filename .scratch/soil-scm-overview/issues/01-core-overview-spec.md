# 01 — Soil-SCM 核心功能规格说明书

**What to build:** 对 Soil-SCM（土壤物理化学数值模式）现有核心功能进行系统化梳理与规格化，形成可指导后续多分层模型、SURFACE 表面络合等架构升级的权威功能文档。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

---

## Problem Statement

Soil-SCM 是一个基于 PHREEQC 地球化学引擎的土壤单点物理化学数值模式，用于模拟长期（数十年）施肥、酸化、淋溶与改良条件下的土壤化学演变。当前项目已具备完整可运行的模拟流程（v0.2.3，51 个测试用例），但其核心功能分散在 12 个源码模块中，缺乏一份从"用户视角"出发的、系统化的功能规格说明书。

用户面临的问题：在规划多分层模型、SURFACE 表面络合、硝化动力学等中期架构升级时，没有一个统一的功能基准文档来：
1. 明确当前系统**承诺提供**的能力边界（做什么）
2. 明确当前系统的**已知局限**（不做什么）
3. 为后续 `to-tickets` 拆分工单提供单一事实来源

## Solution

将 Soil-SCM 的核心功能规格化为一份结构化文档，覆盖：

- **模拟流程**：从配置加载 → 土壤普查数据读取 → 初始条件构建 → 气候强迫生成 → 情景操作 → 逐月化学演化 → 结果输出的完整链路
- **引擎双路径**：官方 PHREEQC（IPhreeqc 3.8.6）与内置简化模式的无缝降级机制
- **情景系统**：5 种预设情景（natural / fertilizer / fertilizer_lime / precip_increase / temp_increase）
- **输出体系**：时间序列 CSV/NetCDF + 绘图，可配置输出变量
- **测试接缝**：3 个约定的测试接口（run_monthly_step / get_action / InitialConditionBuilder）

文档采用本项目的领域词汇（土壤剖面、土壤化学状态、气候强迫、情景操作、月度化学步、诊断输出、引擎模式），不含具体文件路径或代码片段。

## Implementation Decisions

### 架构与模块职责

- **单一模拟管线**：模拟由 9 个阶段构成——配置加载 → 矿物数据库查询 → 土壤普查数据读取 → 初始条件构建 → 气候强迫生成 → 情景操作生成 → 月度化学演化循环 → 结果输出。各阶段职责清晰分离，由不同模块承担。
- **引擎双路径封装**：化学计算统一走 `PhreeqcEngine` 公共接口，内部根据 `engine_mode`（auto/phreeqc/simplified）选择官方 PHREEQC（IPhreeqc 3.8.6）或内置简化动力学模式。`auto` 模式下官方引擎不可用或计算失败时自动降级。
- **状态传递**：模拟状态以"土壤化学状态"（溶液组成、交换位点占据、矿物相质量、气相分压）在月度步之间传递；诊断输出从模拟状态提取，反映化学演化而非过程细节。
- **情景-动作分离**：情景类型与每月干预动作解耦。情景控制器按年/月返回"月度操作指令"（是否施肥、各肥料量、是否施石灰），主循环负责执行；气候修正（降水/温度递增）由气候强迫生成器在生成逐月序列时承担，不通过月度操作指令传递。
- **配置内联优先**：土壤剖面参数、交换性阳离子、降水化学均支持配置内联覆盖，全为 -1 时回退 CSV/JSON 默认值；混合状态（部分 -1 部分有效）报错。

### 化学机理范围

- 离子交换（Gapon 交换）、矿物溶解-沉淀平衡、溶质淋溶（排水模型）、CO₂ 气相平衡为核心机理。
- 施肥物种换算：N→NO₃⁻+H⁺（硝化产酸）、P→H₂PO₄⁻、K→K⁺、Mg→Mg⁺²、Zn→Zn⁺²+SO₄⁻²。
- 石灰换算：CaO 水化为 Ca+OH⁻。
- 降水化学：按当量占比换算为 mol/L，结合入渗水量生成每月 REACTION 输入。
- pH 物理界限放宽至 2.0~12.0，简化模式经验系数集中定义。

### 全局常量收敛

- 简化模式系数、pH 界限、降水入渗系数、矿物量缩放系数统一收敛于常量模块，避免魔法数字散落。

### 输出设计

- 时间序列包含 year/month/time_decimal 时间列 + 可配置变量列。
- 可选诊断列（mineral_mass、solution_ions）以 JSON 字符串存储。
- 输出格式 CSV 与 NetCDF 可切换，NetCDF 缺失自动回退 CSV。

### 领域词汇（本 spec 使用的统一术语）

- **土壤剖面**：由普查数据/配置构建的土壤初始属性集合（pH、CEC、盐基饱和度、有机质、土层厚度等）。
- **土壤化学状态**：PHREEQC 内部化学状态的封装（溶液、交换位点、矿物、气相、体积、温度、pH、pe）。
- **气候强迫**：逐月的降水、温度、pCO₂ 序列。
- **情景操作**：每月的干预指令（施肥/石灰；气候修正由气候强迫承担）。
- **月度化学步**：一次完整的化学演化计算单元（官方或简化路径）。
- **诊断输出**：从模拟状态提取的观测诊断量集合。
- **引擎模式**：auto / phreeqc / simplified 三态。

## Testing Decisions

### 测试原则

- **只测外部行为，不测实现细节**：测试通过公共接口验证能力，内部结构重构不应破坏测试。
- **优先最高接缝**：能通过最高公共接缝覆盖的路径不在更低层重复测试。

### 约定的测试接缝（与本 spec 关联的 3 个接缝）

1. **S1 — 月度化学步（最高接缝）**：验证"土壤化学状态 + 气候强迫 + 情景操作 + 土壤剖面 → 更新后状态 + 诊断输出"的完整月度演化。覆盖：官方/简化双路径、施肥/石灰输入的化学响应、状态在各步间正确传递、降级机制。
2. **S2 — 情景操作**：验证 5 种情景在不同年月的操作指令（施肥月份/石灰月份）生成正确性；气候修正情景（降水/温度递增）验证其不产生施肥/石灰动作，且修正由气候强迫序列承担。
3. **S3 — 初始条件构建**：验证土壤普查数据 → 土壤化学状态的转换（CEC 单位换算、交换位点补齐、矿物量缩放、气相分压）。

### 测试基线

- 现有 pytest 框架（51 用例）作为基线，测试覆盖配置管理、输入读取、初始条件、引擎、降水化学、情景控制 6 个模块。
- 新功能（如多分层、SURFACE）需在约定接缝上补充测试，优先在 S1 接缝扩展。

## Out of Scope

- 多分层（垂直淋溶）模型——属于后续架构升级，本 spec 仅保证单层模型基线。
- SURFACE 表面络合（Hfo_s/Hfo_w）——尚未启用，记录为已知未实现项。
- 硝化两步动力学（尿素→NH₄⁺→NO₃⁻）——未来功能。
- 有机质分解/碳循环模块——长期路线图项。
- 根系吸水/植物吸收——长期路线图项。
- WRF 气候耦合——长期路线图项。
- 参数敏感性自动化扫描——长期路线图项。
- 完整 pip 包结构——长期路线图项。

## Further Notes

- 已知模型局限（记录于项目文档）：单层模型交换性 Al 缓冲库耗尽导致 pH 突升（约第 8 年）；高 pH 下 Al(OH)₄⁻ 两性溶解使总 Al 浓度回升；矿物量折中方案（缩放系数 0.001）压缩了矿物缓冲容量。
- 降水化学默认数据依据《2025年广东省生态环境状况公报》（pH=5.75），离子当量占比 Cl 18.4% / SO4 12.5% / NO3 10.8% / F 2.1% / Ca 20.9% / NH4 15.8% / Na 11.5% / Mg 5.1% / K 1.9% / H 1.0%。
- 本 spec 由 `/to-spec` 生成，作为后续 `/to-tickets` 拆分与架构升级的功能基准。
