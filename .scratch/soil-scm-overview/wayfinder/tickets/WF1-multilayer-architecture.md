# WF1 — 多分层模型架构决策

**Label:** `wayfinder:grilling`
**Status:** open
**Parent:** 多分层模型与 SURFACE 表面络合（wayfinder:map）

## Question

将 Soil-SCM 从单层（n_layers=1）升级为多分层（默认 4 层：0-10/10-20/20-40/40-60cm）时，架构如何设计？

需解析的具体决策：

1. **分层结构的物理表示**：4 个独立"土壤化学状态"实例（各含溶液/交换/矿物/气相），还是单一状态含层索引？
2. **层间垂直迁移机制**：逐月计算后，溶液/溶质如何在下层间传递？候选方案：
   - (a) 完全混合（每层独立平衡，仅水量分配下渗）
   - (b) 一维平流（上层的排水量+溶质浓度作为下层的 REACTION 输入）
   - (c) 弥散/扩散项（物理更完整但复杂度高）
3. **排水模型逐层分配**：`precip_infiltration` 入渗水量如何按层分配（上→下依次下渗）？
4. **接缝设计（S1 最高接缝）**：`run_monthly_step` 的公共接口如何扩展以支持多层——签名变为逐层循环还是整列输入？
5. **配置接口**：`config.yaml` 中 `n_layers` 如何表达；各层参数默认相同、可被外部 CSV/JSON 逐层覆盖（ROADMAP 已确认的设计约束）。
6. **输出扩展**：输出诊断量如何表达逐层（pH_0-10 / pH_10-20 ... vs pH[layer]）？
